# Agile City-Building Game

## Project Overview

This project involved the development of a city-building game using Python and Flask. It was completed as part of a Software Project Management module at Ngee Ann Polytechnic and managed using the Scrum framework.

The game includes multiple gameplay modes, account management, save and load functionality, leaderboards, random events, scoring systems and grid expansion.

## My Role

I served as the Scrum Master and also contributed to software implementation.

My responsibilities included:

- facilitating Sprint Planning, Sprint Reviews and Sprint Retrospectives;
- managing user stories and Sprint tasks using Jira;
- coordinating task allocation and monitoring Sprint progress;
- supporting the resolution of Git and GitHub merge conflicts;
- checking that completed work met the team's Definition of Done;
- contributing to game features and integration.

## Key Features

- Arcade, Free Play and Challenge modes
- User account creation and login
- Separate player profiles and saved games
- Save and load functionality
- Top-10 leaderboard
- Random city events
- Grid expansion
- Coin generation and building upkeep
- Building placement and scoring systems
- Early game termination and progress saving

## Project Management Approach

The project was delivered through multiple Scrum Sprints.

The team used Jira to manage user stories, tasks and Sprint progress. Sprint Reviews were conducted to demonstrate completed increments, while Sprint Retrospectives were used to identify areas for process improvement.

The team also followed a shared Definition of Done covering implementation, testing, integration, peer review and successful merging into the main codebase.

## Challenges and Lessons Learned

The team encountered challenges involving Git merge conflicts, delayed integration and changes in project scope.

These issues were addressed by improving communication before merging, requiring team members to pull the latest code before pushing changes and checking Definition of Done requirements earlier during each Sprint.
